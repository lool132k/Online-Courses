# Проверки первой HTML-версии

Ответственный: Станислав Борцевич. Статус всех браузерных проверок: **не выполнено**. До начала заполнить: дата, ОС, браузер/версия, ширина экрана, способ запуска, коммит. Эти сценарии проверяют прототип, а не весь MVP.

Общие предусловия: открыть `dist/index.html` через локальный HTTP, очистить ключ `names-courses-v1`, отключить расширения, способные менять страницу.

| --- | --- | --- | --- |

# Приоритетные сценарии будущего MVP

| Требования | Положительная проверка | Негативная/граничная проверка |
| --- | --- | --- |
| AUTH | Регистрация, письмо, подтверждение, вход, сброс, выход | Просроченная и повторная ссылка, 5 неудачных входов, старый refresh после выхода |
| ROLE | Заявка teacher и решение admin | Самостоятельное назначение роли, чужой course_id, блокировка последнего admin |
| CAT | Published в поиске, совместные фильтры, 13 курсов на двух страницах | Гостевой запрос unpublished/archived по прямой ссылке |
| COURSE | Каждый разрешённый переход, новая редакция | Запрещённые переходы, возврат deleted на 30-й день и после срока, неизменность старого прогресса |
| MEDIA | Допустимые URL, ready-файл и скачивание авторизованным | 20 МБ и превышение, 10/11 файлов, 100 МБ/превышение, MIME mismatch, чужой доступ |
| LEARN | Последовательность, ручное завершение и повторная запись | Двойная запись, ранний следующий урок, archived без изменения прогресса |
| QUIZ | Pass 70%, fail ниже 70%, лучший результат, повтор после pass | 3-я/4-я попытка, deadline, гонка двух стартов/submit, обрыв сети, неподтверждённые ответы |
| CAB | Среднее лучших результатов и число уникальных студентов | Нет результатов, active/cancelled исключены, чужая статистика закрыта |
| ADMIN | Модерация, роли, деактивация справочника, аудит | Удаление используемой категории, пароли/токены отсутствуют в журнале |
| PERF | Профиль нагрузки ТЗ §6.1 и отчёт p95/ошибок | Потеря подтверждённых ответов, повторные записи/результаты при пике |
| REL | Резервирование и пробное восстановление | Проверка отсутствия секретов в Git, XSS/CSRF/IDOR, восстановление после сбоя |

Эта таблица задаёт покрытие. Детальные кейсы на backend разрабатываются в связанных QA-карточках до реализации модуля.
