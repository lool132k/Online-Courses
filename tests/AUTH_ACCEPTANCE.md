## Интеграция на Supabase — НЕ ПРОВЕДЕНА

| Сценарий | Ожидаемый результат |
| --- | --- |
| Новый email / валидный пароль | Письмо, профиль student, без авторизованного кабинета до подтверждения |
| Регистр email, существующий email | Не создаётся второй пользователь; ответ не раскрывает существование аккаунта |
| Неверный пароль, неподтверждённый email | Вход отклонён |
| Подтверждение один раз / второй раз / истёкшая ссылка | Успех только один раз до истечения; нет токенов в логах |
| Повторное письмо / лимит провайдера | Понятный результат / сообщение об ограничении |
| Подтверждённый вход, refresh, выход | Профиль доступен; после выхода старый refresh отозван |
| Cookie и localStorage | HttpOnly/SameSite; Secure на HTTPS; токенов в localStorage нет |
| POST без Origin / с чужим Origin | 403 |
| Ошибка сети / неверное окружение | Понятная ошибка, нет ложного успеха |
| Прямое чтение профиля другого пользователя через REST | Запрещено RLS |
| Прямой PATCH is_admin/is_teacher/blocked | Запрещён правами таблицы и RLS |
| Регистрация с metadata is_admin=true | Профиль без дополнительных прав |
| Заблокированный пользователь | Все защищённые операции отклонены, в том числе напрямую через REST |
| Две одновременные заявки teacher | Одна pending; вторая отклонена уникальным индексом |
| Мобильный экран 360 / 768 / 1440, клавиатура | Формы читаемы, фокус виден, ошибки у полей |

Сохранять дату, окружение, фактический результат и свидетельство для каждого сценария. Для полного DEV-01 дополнительно пройти сценарии ещё не реализованных требований из docs/AUTH_SETUP.md.
